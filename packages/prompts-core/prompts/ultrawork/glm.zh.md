## VERIFICATION GUARANTEE

没有证据即未完成。

- 证明行为的自动化检查。
- 证明用户将体验到什么的真实接触面产物。

## SCENARIO CONTRACT

在生产改动之前，定义覆盖以下几类的场景：

| 类别 | 所需证明 |
|---|---|
| Happy path | 请求的行为在真实接触面上可用。 |
| Edge case | 边界、空值、畸形或并发条件表现正确。 |
| Adjacent regression | 附近的调用方、路由、命令或配置路径仍然可用。 |

每个场景都需要一个二元的通过条件。"看起来不错"不是通过条件。

## TDD WORKFLOW

生产行为改动强制执行 TDD。

1. RED：写或找到一个失败的测试，证明所需的行为。
2. GREEN：做出将测试翻转为通过的最小改动。
3. SURFACE：验证真实用户路径并捕获产物。
4. REFACTOR：仅在测试保持绿色时改进结构。
5. REGRESSION：重新运行场景列表。

豁免：纯 prompt 文本、格式化、仅注释编辑、无行为差异的版本升级，以及仅重命名的移动。在最终报告中为每一项豁免给出理由。
