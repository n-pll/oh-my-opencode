# Oh My OpenCode 概览

了解 Oh My OpenCode，一个将 OpenCode 转换为最佳代理工具的插件。

## 简介 (TL;DR)

> **Sisyphus 代理强烈推荐 Opus 4.5 模型**。使用其他模型可能会导致显著的用户体验下降。

> **感觉懒吗？** 只需在提示词中包含 **`ultrawork`**（或简称 **`ulw`**）。代理会自动完成所有工作。

> **需要精确？** 按 **Tab** 键进入 Prometheus（规划器）模式，通过访谈创建详细工作计划，然后运行 `/start-work` 来执行完整编排。

> **Oh My OpenCode 为你做什么？**
> - 根据描述构建功能。代理会制定计划、编写代码，并确保其工作。
> - **调试并修复问题**：描述错误或粘贴堆栈跟踪。代理会分析代码库、识别问题，并实施修复。
> - **导航任何代码库**：询问代码库相关的问题。代理会维护对整个项目结构的感知。
> - **自动化繁琐任务**：修复 lint 错误、解决合并冲突、编写发布说明——全部使用单个命令。
> - **你不需要深入思考**。代理已经足够智能，可以独立探索代码库并自行制定计划。

> **它是如何工作的？**
> 1. **代理会自动**：探索代码库以了解现有模式
> 2. **代理会制定计划**：通过访谈了解需求，创建详细任务
> 3. **代理会实现功能**：遵循约定，确保代码工作
> 4. **代理会持续工作**：持续工作直到任务完成
> 5. **代理会追踪进度**：跨会话累积学习成果

> 这就是"只管它"（just do it）模式。全自动工作流程。

> **如果你感觉很懒，只包含 `ultrawork`**（或简称 **`ulw`**）即可。就这么简单。

## 两种工作方式

### 选项 1：Ultrawork 模式（用于快速工作）

如果你感觉很懒，只需在提示词中包含 **`ultrawork`**（或简称 **`ulw`**）即可。

代理将会：
> 1. 探索代码库以了解现有模式
> 2. 研究最佳实践（通过专业代理）
> 3. 根据你的需求制定计划
> 4. 实现功能并验证

**何时使用此模式**：
> 日常编程任务
> 快速原型开发
> 代码库探索
> 简单错误修复

**如何使用**：
> 在你的提示词中包含 `ultrawork`
> 说出你想要什么

**示例**：
```
ultrawork: 为我创建一个 REST API 端点，使用 Express 和 MongoDB
```

---

### 选项 2：Prometheus 模式（用于精确工作）

对于复杂或关键任务，按 **Tab** 键进入 Prometheus（规划器）模式。

**Prometheus 会做什么**：
> 1. **访谈你** - 作为你的个人顾问，提出澄清问题以准确了解你的需求
> 2. **制定计划** - 根据访谈结果生成详细工作计划，包括任务、验收标准和保护机制
> 3. **审查计划** - 可选地由 Momus（计划审查员）审查以提高准确性
> 4. **执行计划** - Atlas（编排器）将任务分发给专业代理

**工作流程**：
> 1. **访谈阶段**（Prometheus）- 通过 Tab 进入 Prometheus 模式
> 2. **计划生成** - Prometheus 创建包含以下内容的详细计划：
>    - 任务列表（原子化、可验证）
>    - 验收标准
>    - 依赖关系
>    - 保护机制（可选：Momus 审查）
> 3. **确认阶段** - 在计划中使用 Tab 键确认
> 4. **执行阶段**（Orchestrator/Atlas）- 将任务分发给专业代理
> 5. **跟踪阶段** - 跨会话累积学习成果

**何时使用此模式**：
> 复杂架构决策
> 需要详细规划的关键功能
> 多团队协作项目
> 生产环境的关键变更
> 重大重构项目

**如何使用**：
> 在你的提示词中包含 Tab 键（Prometheus 认可）

**示例**：
```
Tab 键进入 Prometheus 模式

访谈阶段：
Prometheus: 你的项目需要一个用户认证系统。你打算如何实现？
你: 我打算使用 Next.js 的 NextAuth...
Prometheus: 好的，这很适合。我会创建一个任务来实施它。计划将包含：
- Task 1: 设计数据库 Schema（users, sessions, auth_tokens）
- Task 2: 实现认证 API 端点（/api/auth/*）
- Task 3: 集成 NextAuth 到现有系统
- Task 4: 编写迁移脚本
- Task 5: 测试并部署
```

确认阶段：
Press Tab 键查看任务列表和验证标准

执行阶段：
Atlas 将任务分发给相应的专业代理：
- Librarian: 研究 NextAuth 最佳实践
- Explore: 搜索代码库中的集成示例
- Multimodal Looker: 分析数据库 Schema
- Frontend UI/UX Engineer: 实现登录页面
```

## 关键点

### Prometheus 和 Atlas 是一对

- **Prometheus**（规划器）：负责访谈和计划生成
- **Atlas**（编排器）：负责任务分发和执行
- **Momus**（计划审查员）：可选的高级顾问，用于验证计划准确性

### 两种模式的区别

| 特性 | Ultrawork | Prometheus |
|------|-----------|--------------|
| 自动化 | 完全自动 | 半自动 |
| 速度 | 快速 | 详细但更精确 |
| 适合 | 日常任务 | 复杂项目 |
| 用户输入 | 最小 | 需要访谈 |
| 规划 | 隐性 | 详细计划 |
| 适用场景 | 快速原型 | 架构设计 |

### 配置

代理会根据你的可用提供商自动配置：

```jsonc
{
  "providers": {
    "openai": {
      "claude": {
        "available": true,
        "models": {
          "claude-haiku-4-5": "用于主协调工作",
          "claude-opus-4-5": "用于复杂推理和战略决策"
        }
      },
      "google": {
        "gemini-2-flash": "用于快速开发和前端"
      }
    },
    "fallback_chain": ["openai", "google"]
  }
}
```

你可以在 `~/.config/opencode/oh-my-opencode.json` 中手动调整模型优先级。
